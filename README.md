# 🌐 Overview

During a disaster or emergency, the biggest challenge is often not the lack of
responders — it is the lack of **coordination**.

Emergency reports may arrive from multiple citizens, response teams may operate
with incomplete information, hospitals may not know what is coming, and
authorities may lack a clear district-wide picture.

**SAHAYAK is designed to bring all of them onto one coordinated platform.**

Instead of treating emergency reporting, dispatching, hospital management, and
administrative monitoring as separate systems, SAHAYAK creates a common
operational environment where information flows from the citizen reporting the
emergency to the teams responsible for responding to it.

---

# 💡 The Problem

Traditional emergency-response workflows are often fragmented.

A single emergency may generate multiple reports while different agencies
operate independently with limited visibility into each other's actions.

This can result in:

- Duplicate emergency records
- Delayed identification of critical incidents
- Poor coordination between emergency services
- Inefficient allocation of emergency resources
- Limited hospital-capacity visibility
- Delayed escalation to authorities
- Difficulty maintaining a real-time operational picture

SAHAYAK addresses this by creating a **shared emergency-response network**.

# ✨ Core Capabilities

## 🚨 Citizen Emergency Reporting

Citizens can report an emergency without requiring an operational staff
account.

Reports can include:

- Emergency category
- Incident description
- Location
- Number of people affected
- Additional situational information

The objective is to reduce friction during emergencies while providing
dispatchers with structured information.

---

## 🛰️ Dispatcher Control Room

The dispatcher interface acts as the operational heart of SAHAYAK.

It provides visibility into:

- Active incidents
- Incident severity
- Incident locations
- Available response units
- Ambulance resources
- Fire-response units
- Police units
- Incident status
- Response monitoring
- Merged emergency reports

Dispatchers can use this information to coordinate the appropriate response
from a single console.

---

## 🧠 Intelligent Incident Consolidation

During a major event, multiple people may report the same emergency.

Instead of forcing dispatchers to manually process every report independently,
SAHAYAK is designed around the concept of **incident consolidation**.

```text
3 Citizen Reports
       ↓
Same / Nearby Emergency
       ↓
Incident Correlation
       ↓
1 Operational Incident
       ↓
Coordinated Response
```

This helps reduce information overload while preserving valuable information
provided by multiple reports.

---

## 🚑 Resource Coordination

The platform provides visibility into emergency-response resources such as:

```text
🚑 Ambulances
🚒 Fire Units
🚓 Police Units
🏥 Hospitals
```

Dispatchers can understand which resources are available and coordinate the
response using a common operational view.

---

## 🏥 Hospital Coordination Portal

Hospitals operate through a dedicated interface instead of sharing the same
dashboard as dispatchers.

The hospital portal provides visibility into:

- Available beds
- ICU occupancy
- Total admitted patients
- Incoming ambulances
- Staff availability
- Incoming emergency incidents
- Ambulance tracking
- Capacity information

This enables hospitals to prepare for incoming emergency cases before patients
arrive.

---

## 🏛️ District Authority Command Center

District authorities require a different level of information from operational
responders.

SAHAYAK therefore provides a dedicated command dashboard focused on:

- Total incidents
- Active incidents
- Critical incidents
- Resolved incidents
- Incident distribution
- Response pipeline
- Escalations
- High-priority events
- District-wide situational awareness

This creates an executive-level view of emergency operations without
overloading authorities with dispatcher-level controls.

---

## 👨‍🚒 Field Team Interface

Field teams represent responders operating directly at the emergency location.

The field-team interface is intended to provide:

- Assigned incident details
- Incident location
- Navigation information
- Priority level
- Response instructions
- Operational updates
- Arrival confirmation
- Incident-progress updates
- Completion / resolution updates

# 👥 Role-Based Architecture

| Role | Primary Responsibility | Interface |
|---|---|---|
| 👤 Citizen | Report emergencies | Emergency Reporting Portal |
| 🎧 Dispatcher | Coordinate incidents and resources | Dispatcher Console |
| 👨‍🚒 Field Team | Respond to assigned incidents | Field Operations Interface |
| 🏥 Hospital | Manage medical capacity and incoming cases | Hospital Portal |
| 🏛️ Authority | Monitor district-wide emergency operations | Command Center |

SAHAYAK intentionally provides separate interfaces because each participant
requires different information and controls.

# 🎯 Design Philosophy

SAHAYAK follows four core principles.

## 01 — One Common Operational Picture

All stakeholders should work from synchronized emergency information.

## 02 — Role-Specific Intelligence

Each user should receive only the information and controls relevant to their
responsibilities.

## 03 — Reduce Information Overload

Duplicate reports and operational data should be transformed into clear,
actionable incidents.

## 04 — Coordination Before Complexity

The platform prioritizes communication and response coordination before
unnecessary system complexity.

# 🚀 Running SAHAYAK Locally

SAHAYAK is currently provided as a locally runnable hackathon prototype.

## Prerequisites

Install:

- Node.js
- npm
- Git

Check installation:

```bash
node --version
npm --version
git --version
```

---

## 1. Clone the Repository

```bash
git clone https://github.com/gnan-krp/sahayak-emergency-response-platform.git
```

Enter the project directory:

```bash
cd sahayak-emergency-response-platform
```

---

## 2. Install Dependencies

```bash
npm install
```

---

## 3. Start the Backend

Open one terminal:

```bash
node server.js
```

If your project later uses a separate npm command:

```bash
npm run server
```

---

## 4. Start the Frontend

Open another terminal:

```bash
npm run dev
```

Vite will display an address similar to:

```text
http://localhost:5173
```

Open that URL in your browser.
